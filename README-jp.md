# keynote-skill

[English](README.md)

Apple Keynote (`.key`) を **pptx に変換せずに直接** 読み取り・作成・編集するための Claude スキルです。
[anthropics/skills の pptx スキル](https://github.com/anthropics/skills/tree/main/skills/pptx) の Keynote 版を目指しています。macOS 前提。

## 仕組み

`.key` の中身は `Index/*.iwa`（Snappy 圧縮された Protobuf）です。このスキルは 2 つの経路を使い分けます。

| 経路 | 何をするか | Keynote アプリ |
|---|---|---|
| **ファイル直接**（`keynote_lib.py`） | 読み取り全般（表は表示どおりの値、書式の読み出しも可）、テキスト・ノートの書き換え、位置・サイズ、塗り・線・図形の種類（矢印など）・影・揃え・フォント・行間・箇条書き（レベル、テキストボックスの箇条書き化）・表セルの余白・背景色、タイトルやスライド番号の表示切り替え、グラフのデータ・種類・色・凡例・軸範囲・値ラベル・棒ごとの色 | 不要 |
| **AppleScript**（`keynote_app.py`） | レンダリング（画像・PDF）、スライドやオブジェクトの追加・複製・削除・移動、表・画像・グラフの作成、表セルの書き換え、PowerPoint ファイルの取り込み | 必要 |

AppleScript では塗り色や文字揃えなどが変更できず、逆に直接編集ではスライド追加などの構造変更が危険なので、両者を組み合わせています。
直接編集は編集対象オブジェクト専用のスタイル派生を作るため、同じテーマスタイルを共有する他のオブジェクトには影響しません。
また、未知のフィールドは Protobuf のまま保持し、変更していない `.iwa` はバイト単位でそのまま書き戻します。

## スクリプト

| スクリプト | 用途 |
|---|---|
| `key_text.py` | 内容を Markdown / JSON で出力（タイトル、箇条書き、表、グラフのデータ、画像名、ノート） |
| `key_render.py` | スライドを PNG/JPEG/PDF に書き出し。サムネイル一覧、レイアウト一覧も作成 |
| `key_build.py` | JSON の仕様から新規デッキを生成（テーマ、または既存デッキをテンプレートとして使用） |
| `key_edit.py` | テキスト置換、スタイル・位置の変更を `.key` に直接適用（全スライド一括指定も可） |
| `key_merge.py` | 別のデッキのスライドを、編集可能なまま取り込む（デッキの結合。元のファイルは変更しない） |
| `key_import.py` | `.pptx` を Keynote 書類として取り込み、行間を PowerPoint 相当に補正し、失われた要素（グラフ・フォント）を報告 |
| `key_check.py` | 編集後のファイルの構造検証（`--open` で Keynote で実際に開けるか、`--layout` ではみ出し・テキストの重なりも確認） |
| `keynote_app.py` | インストール済み Keynote の検出、AppleScript の実行、インストール済みフォント名の一覧 |
| `keynote_lib.py` | 上記すべての土台になる Python ライブラリ |

使い方の詳細は [`skills/keynote/SKILL.md`](skills/keynote/SKILL.md)、作業別の手引き [`skills/keynote/references/`](skills/keynote/references/)、各スクリプトの `--help` を参照してください。

## インストール

Claude Code のプラグインとしてインストールします。Claude Code で次を実行してください。

```
/plugin marketplace add ronin-gw/keynote-skill
/plugin install keynote@keynote-skill
```

続けて Python の依存パッケージを入れてください（プラグインは自動では入れません）。

```bash
pip install keynote-parser Pillow
```

更新は `/plugin marketplace update keynote-skill` で行えます。
描画や構造の変更には、Keynote がインストールされた macOS が必要です。

## macOS の権限について

スクリプトはコマンドラインから AppleScript で Keynote を操作するため、初回に macOS が許可を求めます。確認に表示されるのは、コマンドを実行しているアプリ（ターミナル、iTerm2、または Claude Code）の名前で、このスキルの名前ではありません。

| 確認・設定 | 必要か | 何に使うか |
|---|---|---|
| **オートメーション → Keynote**（「…が“Keynote”を制御するアクセスを求めています」） | 描画、新規作成、構造の変更、pptx の取り込みに必須 | デッキを開く、スライドを画像に書き出す、スライドやオブジェクトを追加する、保存する。デッキの読み取りと直接編集（`key_text.py`、`key_edit.py`）は Keynote を使わないので、権限は不要です |
| **オートメーション → System Events**（「…が“System Events”を制御するアクセスを求めています」） | 任意 | `keynote_app.py info` と、Keynote の時間切れエラーだけが使います。Keynote がダイアログを出しているかを調べるためです |
| **アクセシビリティ**（初回に macOS が確認を出します） | 任意 | System Events の許可と合わせて、同じ確認でダイアログの文面とボタン名を読めるようにします |

- **任意の 2 つがある理由**: Keynote にダイアログ（「…を開けません」など）が出たままになると、Keynote を操作するコマンドがすべて止まります。この権限がないと、スクリプトは止まった理由を伝えられません。許可してあれば、`info` がダイアログの文面を表示するので、何を閉じればよいかが分かります。
- **この確認は読み取りだけです。** Keynote のダイアログとその文面を一覧するだけで、ボタンを押す、キーを入力する、他のアプリの画面を読む、といった操作は一切しません。
- **許可しなくても支障はありません。** 任意の権限がなくても他の機能はすべて動きます。`info` はダイアログの文面の代わりに `dialogs not checked: no permission` と 1 行表示します。これはエラーではありません。
- **使わない権限**: 画面収録、フルディスクアクセス、連絡先、カメラ、マイク。このスキルの利用中にこれらを求められた場合、それはこのスキルによるものではありません。
- **確認に出るアプリ名が見慣れないことがあります。** Claude Code がコマンドを実行している場合、「Claude Code」ではなく Claude Code のバージョン番号（例: `2.1.327`）が表示されることがあります。その場合も、このスキルのために許可を求めているのは同じアプリです。
- **確認を拒否した場合**、macOS は再度たずねません。システム設定 → プライバシーとセキュリティ → オートメーション／アクセシビリティ で該当の項目をオンにするまで、スクリプトは `dialogs not checked` と表示し続けます（Keynote 自体を拒否した場合は「権限がありません」のエラーで失敗します）。その間も、権限のあるターミナルで `python3 <スキルのフォルダ>/scripts/keynote_app.py info` を実行すればダイアログを確認できます。
- 許可を取り消すには、システム設定 → プライバシーとセキュリティ → オートメーション（またはアクセシビリティ）でスイッチを切ってください。

## Keynote のバージョンについて

- Keynote 15.x（Keynote Creator Studio、`com.apple.Keynote`）と 14.x 以前（`com.apple.iWork.Keynote`）は別アプリとして共存できます。名前が衝突するため、スクリプトは必ずバンドル ID でアプリを指定します。
- **15.x で保存するとファイル形式が無警告で 26.x に上がり、旧 Keynote では開けなくなります。** そのため既存デッキを扱うときは「そのデッキを開ける中で最も古い Keynote」を自動で選びます（`--app 15` / `--app 14` や環境変数 `KEYNOTE_APP` で上書き可）。直接編集はファイル形式を変えません。
- 動作確認: macOS 27.2 上の Keynote 15.4（形式 26.4.0）と Keynote 13.2（形式 13.2.1）、および 2018 年作成のデッキの読み取り。
- デコードには [keynote-parser](https://github.com/psobot/keynote-parser)（公式対応は 14.5 まで）を使っています。15.4 のファイルには未知のフィールドが数個ありますが、保持されたまま往復できることを確認しています。

## 対応していないもの

ビルド（オブジェクトのアニメーション）、ハイパーリンク、グループ化、ムービー・オーディオ、コメント、レイアウト（マスター）の変更を既存スライドへ反映すること、パスワード付きデッキの直接読み取り、Keynote '09 形式。

## テスト

```bash
pytest tests                    # ファイルの読み書きのテスト
KEYNOTE_TESTS=1 pytest tests    # Keynote アプリを操作するテストも実行
```

テスト用のデッキはリポジトリに含めていません（Apple のテーマ素材を含むため）。
初回の実行時に、インストール済みの Keynote で `tests/fixtures/spec.json` から自動で作成し、`tests/fixtures/` に保存します（Git の管理対象外）。2 回目以降は Keynote なしで実行できます。

- Keynote 15 以降と 14.x 以前のそれぞれについてデッキを作ります。片方しか入っていない場合、もう片方のテストはスキップされます。
- Keynote が入っていない環境では、デッキを使うテストはすべてスキップされます。
